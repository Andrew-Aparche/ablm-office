# 에이블램 에이전트OS 오피스 열기

플러그인의 오피스(`app/server.mjs`)만 이 PC에서 띄우고 브라우저를 여는 런처다.
대표님은 데스크탑 앱의 대화와 허락 버튼만 사용한다. 명령을 복사해서 다른 창에 실행하도록 시키지 않는다.
아래 기술 설명은 에이전트용이다. 대표님께 하는 말에는 **PowerShell·터미널·세션·MCP·config**라는 단어를 쓰지 않는다.
항상 **대표님**으로 부르고 짧은 존댓말로 안내한다. 앱 버전·언어에 따라 버튼 이름은 다를 수 있다.
오피스는 대화가 끝나도 유지한다. 닫아 달라는 요청 없이 닫지 않는다.

## 1. 오피스 도구부터 호출

플러그인의 `ablm-office-launcher` MCP 서버가 제공하는 `office` 도구를 우선 사용한다.
검색형 도구라면 먼저 `ablm-office-launcher office`를 찾는다. 설정 파일을 먼저 수정하지 않는다.

- 열기: `office({"action":"open"})`
- 닫기: `office({"action":"close"})`
- 상태: `office({"action":"status"})`
- 테스트에서만 브라우저 생략: `office({"action":"open","openBrowser":false})`

Codex 대화형 호스트에서는 별도 `approval_mode="approve"` 설정 없이 도구 호출의 표준 승인 요청을 사용할 수 있다.
허락이 필요하면 호스트가 띄우는 요청에서 **사용자가 직접** 허용한다. 에이전트가 버튼을 누르거나 승인을 대신 응답하지 않는다.

> 대표님, 오피스를 열겠습니다. 앱에 허락 창이 뜨면 내용을 확인하고 **허용**을 눌러 주세요.

`항상 허용` / `Always allow`가 실제로 보이면 선택 사항으로만 설명한다. 필수가 아니며, 오피스의 `office` 도구에 한정된 허락인지 확인한다.
로컬 0.164.0의 승인 요청에는 `session`·`always` 선택 정보가 있지만 모든 데스크탑 버전의 버튼 문구를 보장하지 않는다.
명령 실행 허락 창에서 영구 규칙 저장을 안내하지 않는다.

> 대표님, 이 오피스만 다음에도 허락하시려면 **항상 허용**이 보일 때 선택하셔도 됩니다. 이번만 허용하셔도 열 수 있습니다.

호스트가 설치된 도구 프로세스를 시작하므로 셸의 로컬 포트 제한을 피할 수 있다. 단, 호스트·관리자 정책은 여전히 적용된다.
이 도구는 세 동작과 브라우저 열기 여부만 받으며 임의 명령·경로·외부 URL은 받지 않는다.

## 2. 도구가 안 보이면: 앱 안에서 해결

설치 직후 같은 대화에 새 도구가 반영된다고 가정하지 않는다. 공식 안내는 설치 후 **새 대화**다.
하지만 대표님께 대화를 바꾸라고 하기 전에, 이 스킬을 읽었고 설치된 런처 경로와 실행 도구가 있으면 **먼저 아래 3절의 앱 승인 실행을 시도한다**.
대표님은 지금 대화에서 허락 버튼만 누르면 된다.
3절을 쓸 수 없을 때(런처 파일 없음, 실행 도구 없음, 사용자 승인 UI 없음)만 앱의 플러그인 화면 확인과 새 대화를 쉬운 말로 안내한다.

> 대표님, 앱의 **플러그인**에서 **에이블램 에이전트OS 오피스**가 켜져 있는지 확인해 주세요. **새 대화**를 누르고 **에이블램 오피스 열어줘**라고 보내 주세요.

새 대화에서도 설치본이 없거나 실행 도구가 없으면 **플러그인 → 업데이트**(보일 때)를 안내한다.
임의의 비슷한 경로·다른 설치본을 추측하거나 같은 실패를 반복하지 않는다.

## 3. 설치된 런처로 실행하는 대안 (에이전트만 실행)

런처 경로는 이 SKILL.md의 절대 경로에서 `skills/ablm-office/SKILL.md`를 떼어낸 폴더 + `launcher/launch.mjs`다.
Claude Code에서는 `${CLAUDE_PLUGIN_ROOT}/launcher/launch.mjs`도 사용할 수 있다.
파일 존재를 확인하고 공백·한글이 있는 경로도 인수 하나가 되도록 따옴표로 감싼다. 아래 예시 경로를 그대로 실행하지 않는다.

```sh
node "<plugin-root>/launcher/launch.mjs"
node "<plugin-root>/launcher/launch.mjs" --status
node "<plugin-root>/launcher/launch.mjs" --stop
```

위 세 줄은 각각 열기·상태·닫기 중 **요청한 하나만** 실행한다.
Codex의 기본 샌드박스에서 실행이 `listen EPERM` / 즉시 종료 / 쓰기 권한 오류로 실패하면,
현재 정책이 `on-request` 또는 해당 표준 승인을 허용할 때만 **정확히 같은 설치된 런처 동작**을 샌드박스 밖 실행 승인으로 요청할 수 있다.
예: `exec_command`의 `sandbox_permissions="require_escalated"`와 아래 `justification`을 사용한다.
`prefix_rule`·exec 규칙 추가를 요청하지 않는다. 허락 요청은 해당 동작 1회로 한정하고 사용자가 앱에서 누를 때까지 기다린다.

> 대표님, 오피스를 여는 데 한 번 더 허락이 필요합니다. 앱에 나온 실행 내용을 확인하고 **이번만 허용**을 눌러 주세요.

사용자 승인 UI가 제공되는 경우에만 이 대안을 요청한다. `auto_review`처럼 자동 심사만 가능한 환경에서 이를 사용자 허락으로 간주하지 않는다.
호스트가 이 기능을 제공하지 않거나 `never` 정책이면 실행을 강제하지 않는다. 사용자 거절·관리자 차단·자동 승인 심사 거절 뒤에 이 대안을 우회로로 쓰지 않는다.
Windows의 격리 구현은 Mac과 다르며 일부 환경은 명령 종료 때 자식 프로세스를 정리한다. `detached`만으로 권한이나 생존이 보장되지 않는다.
URL·상태 확인이 실패하면 열렸다고 말하지 않는다. 앱의 새 대화에서 도구를 다시 연결하거나 담당자에게 오류를 전달하도록 안내한다.

> 대표님, 앱에서 오피스를 열지 못했습니다. **플러그인**에서 오피스를 확인한 뒤 **새 대화**에서 다시 부탁해 주세요. 계속 막히면 보이는 오류를 도와주시는 분께 보여 주세요.

## 4. 열린 결과 전달

출력의 `에이블램 에이전트OS 오피스: http://127.0.0.1:<port>/?t=<token>` 전체 주소를 대표님께 그대로 전달한다.
`?t=` 뒤는 이번 실행의 출입증이다. 주소를 자르거나 바꾸지 않는다. 브라우저가 안 열리면 이 링크를 누르도록 안내한다.
`already running`이면 같은 오피스를 재사용한다. 오류·승인 대기·주소 없는 결과를 성공으로 보고하지 않는다.

> 대표님, 오피스가 열렸습니다. 아래 주소를 눌러 주세요. 이 주소는 오피스 열쇠이니 다른 분께 보내지 말아 주세요.

## Node.js가 없거나 오래됐을 때

Node.js 20 이상이 필요하다. 도구 시작 실패만으로 미설치라고 단정하지 않는다.
에이전트가 `node --version`으로 없거나 v19 이하임을 확인했거나 런처가 최소 버전 오류를 낸 경우에만 안내한다.
Node.js를 대신 설치하거나 설치기를 자동 실행하지 않는다.

> 대표님, 오피스에 필요한 **Node.js**라는 무료 프로그램을 준비해 주세요. https://nodejs.org 에서 **LTS** 설치 파일을 받아 열고 안내대로 설치해 주세요. 끝나면 앱을 완전히 껐다 켜고 **에이블램 오피스 열어줘**라고 보내 주세요.

## CLI/자동 실행(`codex exec`)용 선택 사항

`launcher/setup-codex.mjs`는 비대화형 실행에서 승인 창을 받을 수 없는 운영자를 위한 선택 도구다. 데스크탑 설치·첫 실행의 필수 단계가 아니다.
이 도구는 명시적으로 동의한 경우에만 사용자 설정의 `office` 한 개에 `approval_mode="approve"`를 저장한다.
현재 흐름에서는 에이전트가 설정 프로그램을 실행하거나 동의 문자를 대신 입력하지 않는다. 운영자가 CLI 자동 실행을 별도로 요청할 때만 기술 안내를 제공한다.
`codex exec`의 `never` 승인 오류를 대화형 앱에서도 불가능하다는 증거로 취급하지 않는다.

## 안전선

- `--dangerously-*`, `danger-full-access`, 전역 샌드박스·승인 정책 변경, 네트워크 전체 허용을 사용하거나 안내하지 않는다.
- exec 규칙을 몰래 설치하거나 `nohup`·별도 앱·detached를 권한 우회 수단으로 사용하지 않는다.
- 사용자의 거절과 관리자 정책 차단을 따른다. 승인 창을 에이전트가 조작하지 않는다.
- 오피스 런처의 `127.0.0.1` 전용 동작을 유지한다. 외부 공개 주소로 바꾸지 않는다.
